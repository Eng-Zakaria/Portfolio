The Problem

Estates data work is hard to show. Registers, CAFM work orders, meter readings and BIM models belong to clients, under confidentiality — so the most interesting pipelines usually stop at the client's firewall, and portfolio demonstrations either leak data or prove nothing.

This portfolio takes that constraint seriously: 20 estates projects, drawn from freelance client engagements, rebuilt end-to-end on a synthetic campus whose ground truth is known — plus public open data where realism demands it. Nothing real is exposed, and every number is still checkable against a test or an acceptance document.

Approach & Implementation

  • Synthetic by Design: every figure comes from a campus_synth foundation generator that also emits a known ground truth and planted defects; public open sources (DESNZ factors, BDG2, OpenStreetMap) are used where realism demands. Client data is never involved, provenance for every public dataset is tracked in DATA.md, and every chart carries a synthetic-data footer.
  • Foundation (F): 17 truth tables and 7 deliberately messy exports — merged cells, mixed date formats, stuck sensors — with 20 tests at 96% coverage, ruff and mypy strict clean, and a 17–20 s small-profile generate that keeps the dev loop fast.
  • Lakehouse (P01): bronze → silver medallion ingestion with data contracts, idempotent re-runs and quarantine; all 8 sources reconciled row-by-row with zero unexplained loss in a ~35 s ingest.
  • Orchestration (P02): 7 Airflow DAGs with watermarks, schema-drift quarantine and failure alerting — a deliberately corrupted file is routed to quarantine and raises an alert through Mailpit.
  • Data Quality (P03): 133 YAML checks compiled to Great Expectations and DuckDB with weighted scoring, alerting and 100% defect recall against the planted ground truth.
  • dbt Project (P04): dbt build green — 196 pass / 0 errors from 147 data tests plus 2 unit tests, 100% of models tested, 292/292 columns documented, 21 contracts, plus silver→gold reconciliation of every mart.
  • CI/CD for Data (P05): ci, nightly, docs, release and security workflows: lint + types → pytest → small-profile build → dbt build → data-quality gate → sqlfluff + MkDocs + compose checks on every push.
  • Dashboards & Returns (P06–P10): space utilisation (frequency × occupancy plus sensor-observed occupancy), asset & maintenance (backlog, SLA, lifecycle and renewal forecasts), net-zero carbon (Scope 1/2 on fetched DESNZ factors, baseload analysis), a statutory-compliance tracker with weekly digest, and a mock HESA/TRAC-style return — each with validation SQL and a Power BI handoff.
  • BIM & Standards (P11–P14): IFC → analytical tables with a model QA report that finds every planted defect; a COBie validator with a handover loader; a Uniclass mapper measuring 97.81% top-1 accuracy against a 21.49% fuzzy baseline; and an ISO 19650 naming/metadata checker with 20 rules at 94% coverage.
  • Building Systems (P15–P17): MQTT → Node-RED → TimescaleDB → Grafana ingestion (84,435/84,435 valid messages, 141 dead-lettered, 20/20 planted faults detected); energy-anomaly detection over 210 injected faults ranking the planted findings #1 and #2; and air-quality/occupancy analytics on 15-minute sensor data with 38 tests.
  • Twin, Spatial & Governance (P18–P20): a canonical-ID crosswalk with Brick Schema and a FastAPI context API; an OpenStreetMap-footprint spatial carbon map with heat clusters and isochrones; and a governance pack — metric registry, glossary, dashboard guides, runbooks and a training kit — held together by 126 tests.
  • Honest Scope: all 20 projects plus the foundation are delivered and evidenced in dated acceptance docs. Recorded gaps stay visible: the P15 live Docker stack was not exercised in the build environment, and P13 classifies against a clearly named dev placeholder until the official NBS tables are fetched (it refuses final runs).

Challenges & Solutions

Challenge: Showing Client Work Without Exposing It

The real workflows come from freelance client engagements — registers, meters, BIM models — and client data is confidential and cannot be published.

Solution: Rebuild Everything on Synthetic + Public Data

A generator with known ground truth reproduces the messy exports (and plants defects to measure detection against), public datasets supply realism where it matters, and DATA.md records provenance for every source.

Challenge: 20 Projects Becoming Unmaintainable Demos

Twenty separate mini-projects tend to fragment into code that only its original author can run, with no shared assumptions.

Solution: One Foundation Generator + Per-Project Acceptance Docs

All data descends from a campus_synth generator that also produces ground truth, and each project ships an acceptance document defining what "done" means.

Challenge: Silent dbt Breakage

Refactors and schema changes break models quietly — a green build can still be serving wrong columns to a mart.

Solution: 196 Tests + 21 Contracts Gated in CI

Every model is tested and every column documented; contracts run as part of the CI chain, so a breaking change fails the build instead of shipping quietly.

Challenge: Reconciling 8 Ingested Sources

With eight feeds landing in one warehouse, rows get dropped or double-counted and nobody notices until a total looks wrong.

Solution: Zero-Loss Reconciliation Against Ground Truth

Because the generator knows the expected counts, ingestion is reconciled source by source and all 8 land with zero loss, verified rather than assumed.

Challenge: Spatial Work Unusable by Non-GIS Analysts

Footprints, clusters and isochrones are meaningless to anyone without a GIS toolchain open next to the dashboard.

Solution: Standard GIS Exports + Power BI Map Handoff

Results are exported as gpkg, geojson, topojson, PNG and QML alongside a Power BI map handoff, so the analysis leaves the GIS world and lands where the business already works.

Outcome

All 20 projects plus the foundation are delivered and evidenced: the whole chain is reproducible from a single make ci, 196 dbt tests pass with 21 contracts enforced, 8/8 sources reconcile with zero loss against ground truth, and 133 data-quality checks measure 100% defect recall. Every project has a live interactive demo generated from the same marts the tests and acceptance docs quote.

The constraint made the work stronger: because client data cannot be exposed, correctness was measured against known ground truth instead of assumed. What remains open is stated plainly in STATUS.md — the P15 live stack and the P13 official code tables — rather than implied.
