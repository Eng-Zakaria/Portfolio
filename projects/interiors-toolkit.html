The Problem

Interior documentation is repetitive but unforgiving: every project needs walls, openings, rooms, finishes, outlets, fixtures, lighting and sheets built in the right order, plus quantities a client can price. Doing that by hand in Revit is slow, and the same model has to survive being regenerated — not just once, but on demand, in batch, on a machine with no human sitting in front of it.

The tooling gap is on both sides. A pyRevit script is fast to write but cannot ship as a compiled DLL for Design Automation, and Revit itself is stateful and modal — so the moment you try to automate a whole portfolio, dialogs hang and run logs vanish. Meanwhile, parametric specs quietly drift away from the geometry they were supposed to describe, and there is no audit trail proving what was built.

Approach & Implementation

  • Parametric Portfolio: 10 specs, P01–P10, spanning a 45 m² studio through a 250 m² courtyard villa and a 240 m² boutique office — residential and commercial in one generated set.
  • Deterministic Build Order: levels → grids → walls → doors/windows → rooms (+ finishes) → electrical / plumbing / furniture / lighting → sheets, so every model is built the same way.
  • Native + Open Outputs: native .RVT for Revit 2026, IFC4 backups written with ifcopenshell, PNG floor plans and 3D renders, plus a gallery report.
  • Quantities Per Project: rooms, doors/windows, electrical and plumbing outlets, lighting/fixtures and sheets are captured for every model; hero projects P06 penthouse, P07 office and P08 villa each carry 5 sheets.
  • Compiled C# Add-in: Interiors.Batch (net48) with BatchBuildCmd and ResizeChairsCmd as IExternalCommands — one outer TransactionGroup with a Transaction per item and per-item try/catch, at parity with the pyRevit script.
  • Headless-Safe Execution: configuration comes from environment variables (PROJECT_JSON, HEADLESS, CHAIR_FILTER, CHAIR_TO_MM, CHAIR_ROOMS) and TaskDialog is deliberately omitted, because modal input blocks the Revit Batch Processor and Design Automation runs. Ships with a .addin manifest and a Batch Processor starter manifest.
  • CI Without Revit: RevitApiStubs.cs lets the project compile with Revit absent from the machine, with 36 pytest files and GitHub CI on top.
  • Audit Trail: P06 verifies at 12 walls, 11 doors, 7 windows, 9 rooms and 5 sheets; schema v2 validation reports 0 audit errors, and build/export logs are written per project.
  • Cost Roll-Up & BI: the priced BOQ totals $156,733 across the portfolio, and Power BI-ready CSVs land in out/plans/.

Challenges & Solutions

Challenge: Scripting Can't Ship to Design Automation

pyRevit scripting was fine interactively, but Design Automation needs a compiled DLL and pyRevit cannot produce one.

Solution: A net48 Add-in With Stub-Based CI

Built the C# Interiors.Batch add-in alongside the script, using RevitApiStubs.cs so CI can compile it without Revit installed, and environment variables for all configuration.

Challenge: Modal Dialogs Hang Headless Runs

Revit is stateful and modal: a TaskDialog waiting for a click will stall the Batch Processor and Design Automation indefinitely.

Solution: No Dialogs, Explicit Headless Guard

TaskDialog is deliberately omitted, a HEADLESS guard switches behaviour, and progress goes to file logs under %TEMP%\Interiors.Batch\ so results survive without a UI.

Challenge: Specs Drifting From Built Geometry

A parametric spec can be edited freely while the model in Revit stays as it was, leaving no proof of what was actually built.

Solution: Schema v2 Validation + Build Logs

Schema v2 validation audits every project against its spec (0 audit errors on the current portfolio), and per-project build/export logs form a traceable audit trail.

Challenge: Getting Quantities and Cost Out of Revit

Clients want priced bills of quantities, but Revit is a modelling tool, not a cost roll-up — the numbers have to come from somewhere reliable.

Solution: Same Spec Drives Geometry and Numbers

The priced BOQ and Power BI-ready CSV exports are generated from the identical spec that drives the geometry, so quantities and cost can never contradict the model.

Outcome

10 openable native Revit models a recruiter can double-click, each with IFC4 backups, PNG plans and renders, and a quantified cost roll-up totalling $156,733 across the portfolio. Every number is reproducible because it comes from the same spec that built the geometry.

The C# add-in makes the identical build repeatable in batch: same transactions, same results, no Revit licence needed for CI to prove it compiles.
