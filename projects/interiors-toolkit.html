The Problem

Interior documentation is repetitive but unforgiving: every project needs walls, openings, rooms, finishes, outlets, fixtures, lighting and sheets built in the right order, plus quantities a client can price. Doing that by hand in Revit is slow, and the same model has to survive being regenerated — not just once, but on demand, in batch, on a machine with no human sitting in front of it.

The tooling gap is on both sides. A pyRevit script is fast to write but cannot ship as a compiled DLL for Design Automation, and Revit itself is stateful and modal — so the moment you try to automate a whole portfolio, dialogs hang and run logs vanish. Meanwhile, parametric specs quietly drift away from the geometry they were supposed to describe, and there is no audit trail proving what was built.

Architecture

Approach & Implementation

  • Parametric Portfolio: 10 schema v2 JSON specs, P01–P10, from a 45 m² studio to a 250 m² two-level villa and a 240 m² office. Nine carry full MEP, furniture and lighting; P05 is an architecture-only sketch shell.
  • Deterministic Build Order: levels → grids → walls → doors/windows → rooms (+ finishes) → electrical / plumbing / furniture / lighting → sheets, so every model is built the same way.
  • Native + Open Outputs: native .RVT for Revit 2026 built through pyrevit run (9 projects; P05 exists as IFC and plan only), IFC4 files written from the specs with ifcopenshell, matplotlib plan PNGs, Revit view exports for P01–P04, and an HTML build report.
  • Quantities Per Project: rooms, doors/windows, electrical and plumbing points, furniture, lighting and sheets are counted per project; P06, P07 and P08 each carry 5 sheets. Fixtures are placed as template families carrying the spec's Manufacturer/Model/Price parameters; views are listed in the log, not created.
  • C# Add-in (in progress): Interiors.Batch (net48) with ResizeChairsCmd (complete: one outer TransactionGroup, a Transaction per change) and BatchBuildCmd, a skeleton that validates and logs a project plan but does not create elements yet. The models were built by the pyRevit path.
  • Headless-Safe Execution: configuration comes from environment variables (PROJECT_JSON, HEADLESS, CHAIR_FILTER, CHAIR_TO_MM, CHAIR_ROOMS); there is no text-input dialog, and HEADLESS=1 suppresses the summary TaskDialog, because modal UI blocks Batch Processor and Design Automation runs. A sample .addin manifest is in the README and a Batch Processor config is in tools/.
  • Tests Without Revit: the core logic is pure, IronPython-safe Python, covered by 12 pytest files (54 tests, all passing) that GitHub CI runs on Windows; RevitApiStubs.cs lets the C# project compile without Revit installed (CI does not build it yet).
  • Audit Trail: 0 schema v2 validation errors and 0 audit issues across all specs; 9 per-project Revit build logs with empty error lists; reopened models verified for P06 (12 walls, 11 doors, 7 windows, 9 rooms) and P08 (17 walls, 9 doors, 8 windows, 10 rooms).
  • Cost Roll-Up & BI: the BOQ totals $156,733 across nine priced projects (219 rows of fixtures, furniture and lighting, at illustrative unit prices typed into the specs; no walls, finishes or labour), written as flat CSVs to out/plans/.

Challenges & Solutions

Challenge: Scripting Can't Ship to Design Automation

pyRevit scripting was fine interactively, but Design Automation needs a compiled DLL and pyRevit cannot produce one.

Solution: A net48 Add-in With Stub-Based CI

Started the C# Interiors.Batch add-in alongside the script, with RevitApiStubs.cs so it compiles without Revit installed and environment variables for all configuration. The chair-resize command is complete; the batch build command still only validates and logs.

Challenge: Modal Dialogs Hang Headless Runs

Revit is stateful and modal: a TaskDialog waiting for a click will stall the Batch Processor and Design Automation indefinitely.

Solution: No Dialogs, Explicit Headless Guard

No text-input dialogs; a HEADLESS=1 guard suppresses the summary TaskDialog, and progress goes to file logs under %TEMP%\Interiors.Batch\ so results survive without a UI.

Challenge: Specs Drifting From Built Geometry

A parametric spec can be edited freely while the model in Revit stays as it was, leaving no proof of what was actually built.

Solution: Schema v2 Validation + Build Logs

Schema v2 validation checks every spec (0 errors), the audit checks the spec-derived inventory (0 issues), and per-project Revit build logs record what was actually created, so spec counts and built counts can be compared.

Challenge: Getting Quantities and Cost Out of Revit

Clients want priced bills of quantities, but Revit is a modelling tool, not a cost roll-up — the numbers have to come from somewhere reliable.

Solution: Same Spec Drives Geometry and Numbers

The BOQ CSVs are generated from the same spec that drives the geometry, so they are reproducible without Revit. They prove the spec is consistent; checking them against the saved model is the next step.

Outcome

Nine native Revit 2026 models built from spec, IFC4 files and plan PNGs for all ten projects, and a BOQ totalling $156,733 at demo prices across nine projects. Every number is reproducible because it comes from the same spec that built the geometry, and every build left a log.

The validation, audit and BOQ logic runs and is tested without Revit. The C# add-in for headless batch builds is started but does not create elements yet.
