The Problem

A digital bank needs core-banking operations, real-time transaction processing, and market-data intake to work as one system while staying auditable and resilient under failure.

It also needs fraud/AML screening and BNPL credit scoring on top of the same data, served through a unified API gateway with wallet support — without tangling services, storage, and orchestration together.

Approach & Implementation

  • Service split: core-banking API in Python plus a dedicated transaction service in Java, keeping account logic separate from high-volume transaction writes.
  • Streaming backbone: core-banking events, transaction records, and market feeds publish to Kafka topics for decoupled, replayable ingestion.
  • Polyglot storage: PostgreSQL for system of record, MongoDB for flexible documents, Redis for caching/sessions, and Elasticsearch for transaction search.
  • Risk & credit ML: fraud/AML models screen transaction streams while a BNPL scoring module evaluates installment eligibility from account and behavior features.
  • Orchestration & serving: 3 Airflow DAGs orchestrate ingestion, feature prep, and scoring refreshes; FastAPI behind a Kong gateway serves clients with Web3 wallet flows, all containerized with Docker and monitored end to end.

Challenges & Solutions

Challenge: Mixed workloads on one database

Transactional writes, analytical reads, document shapes, and search queries pull storage in conflicting directions.

Solution: Purpose-built stores behind Kafka

Kafka decouples producers from consumers so each store serves one job: Postgres for records, MongoDB for documents, Redis for speed, Elasticsearch for search.

Challenge: Risk checks vs. checkout speed

Fraud/AML screening and BNPL scoring must run on fresh data without blocking the payment path.

Solution: Async scoring with gateway serving

Airflow DAGs refresh features and scores on schedule while the FastAPI + Kong layer serves decisions and wallet operations from precomputed, monitored state.

Outcome

The platform connects banking services, streaming, storage, ML risk scoring, and API delivery into one coherent architecture with clear service boundaries.

Airflow orchestration, containerized deployment, and end-to-end monitoring make the data flows repeatable and observable for enterprise operation.
