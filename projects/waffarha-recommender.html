The Problem

Waffarha shows thousands of time-limited offers, and the app needs a personal shortlist for every customer. The behavioral data lives in MoEngage exports on Google Cloud Storage, the offer catalog lives in ClickHouse, and the app reads recommendations from MySQL on AWS. The job was to connect all three every night without ever recommending an expired offer.

Pipeline

StageWhat happensWhere
1List and download the last day of MoEngage JSON / NDJSON event exports, cached locallyGoogle Cloud Storage
2Keep only offer-view and search-click events; extract user, offer, and timestampPython
3Build ordered per-user histories, drop consecutive duplicates, keep the latest 50Python
4Item-to-item co-view cosine similarity, minimum-support filter, top 200 neighbors per itemNumPy
5Recency-weighted scoring, then filter to offers that are still activeClickHouse
6Upsert top-N recommendations per user in 5,000-row batches through an SSH tunnelMySQL on AWS RDS via EC2

Engineering Decisions

  • Fail open, never fail the night: if ClickHouse is unreachable the batch still completes without the active-offer filter, so the app never wakes up to an empty recommendations table.
  • Similarity you can explain: co-occurrence cosine, co_views(i, j) / sqrt(users(i) · users(j)), with a minimum user count so one shared click can't create a fake neighbor.
  • Idempotent loads: upserts keyed on the user, so a re-run replaces yesterday's picks instead of duplicating them.
  • Operable by non-engineers: a Google-sign-in dashboard shows run status and a "run now" button that refuses to start a second run while one is in flight.
  • Shipped like software: containerized and built through a Jenkins pipeline from the team's Bitbucket repository.

V2: Purchase-Based Hybrid Ranker

A second generation is code-complete alongside the nightly V1 job: purchase-based collaborative filtering with popularity damping, a content boost from the customer's last purchases, MMR diversification (λ = 0.7) with a per-merchant cap, and a trending fallback for new users. A gradient-boosted ranker scores five features (CF, popularity, discount, units sold, content). The local training manifest covers 23,624 users, 431 items, and 32,671 similarity edges.

Outcome

Every customer with recent activity starts the day with fresh, active-offer recommendations, built from the previous day's behavior across two clouds, with no manual step between the event export and the app.
